# Log Homes International — Website Starter

Next.js 16 + TypeScript + Tailwind + Motion (Framer Motion) + Lenis. This is
the Site B (Oman/Gulf) starter from the build scope doc, sharing its design
system and component library with the Log Homes India site rather than a
separate design. Every primary page is built and wired into navigation.
Content throughout is placeholder where real assets aren't available yet
(see the map further down) — this is English-only for now; Arabic/RTL is
planned once that copy is provided (see the note further down).

## Internationalization (English now, Arabic/RTL later)

This is deliberately English-only for now — built ahead of the Arabic copy
being ready, per the decision to not block the Oman site on translation.
There's no `/en/`-`/ar/` locale routing yet; adding it is a deliberate
follow-up task, not a trivial toggle, since it touches routing, the
language-switcher component mentioned in the build scope doc, and RTL
layout handling (logical CSS properties instead of left/right, mirrored
icons, etc.) — budget it as real work when Arabic copy arrives, not a
same-day add.

## Quick start

```bash
npm install
npm run dev
```

Open http://localhost:3000. `npm run build` produces a production build.

Requires network access to fonts.googleapis.com at build time (next/font
fetches Fraunces + Inter from Google Fonts on first build/dev run).

## Contact form setup

The contact form sends real email via an API route now — it needs a few
environment variables to actually work. Copy the example file and fill it in:

```bash
cp .env.local.example .env.local
```

See the comments in that file for exactly what each value is and where to
get it (a Resend API key + the owner's inbox address, and Cloudflare
Turnstile site/secret keys). **Cloudflare's own published dummy Turnstile
keys are already in the example file**, so the form is fully clickable and
testable with zero setup — you just won't get a real email until
`RESEND_API_KEY` and `CONTACT_TO_EMAIL` are filled in, and the dummy
Turnstile keys accept any submission as human, so both must be replaced
with real ones before launch.

See the build scope doc's Section 11 for why this stack (Resend + Turnstile
+ a honeypot field + in-memory rate limiting, no database) was chosen.

## Motion & interaction

Built on `motion` (the current, actively-maintained package — what used to
ship as `framer-motion`; that name still works but `motion` is the one to
install going forward) plus `lenis` for smooth scroll.

| Component | What it does |
|---|---|
| `SmoothScroll.tsx` | Global Lenis smooth-scroll, mounted once in `layout.tsx` |
| `CustomCursor.tsx` | Spring-follow cursor; expands + labels "View" over project cards |
| `MagneticButton.tsx` | Wraps a button/link, pulls it gently toward the cursor within its bounds |
| `SplitHeading.tsx` | Word-by-word masked reveal for major headings |
| `RevealImage.tsx` | Scale-in + curtain-wipe reveal for image/placeholder blocks on scroll |
| `TiltCard.tsx` | Mouse-tracked 3D tilt, used on project cards |
| `NoiseOverlay.tsx` | Fixed, near-invisible film-grain texture over the whole page |
| `ScrollProgressBar.tsx` | Thin gold bar at the very top, tracks scroll position |
| `Reveal.tsx` / `lib/motion.ts` | Generic fade-up-on-scroll wrapper + shared variants |

All of it respects `prefers-reduced-motion` (checked in each component,
plus a global CSS fallback in `globals.css`) and the custom cursor/hide-
native-cursor rule only engages on `(pointer: fine)` devices, so touch
never gets a stuck invisible cursor.

I deliberately hand-built these rather than pulling components from a
registry like 21st.dev — most of the polished ones there require their
own API key/account, and for a real client codebase, bespoke components
matched exactly to this palette beat generic ones pulled from a public
registry.

GSAP + ScrollTrigger for the pinned Materials scrollytelling described in
the build scope doc still isn't wired in — the current Materials section
uses `RevealImage` as a lighter-weight placeholder for that.

## "Wow" interactive features — currently disabled

Three of the five feature ideas from the build scope doc's Section 9 were
built, then **disabled per feedback that they weren't up to the mark yet**
(specifics pending). Nothing was deleted — each component file is intact
in `components/`; only the import and JSX usage are commented out in
`app/page.tsx` (DayNightShift) and `app/materials/page.tsx`
(NotchExplode, WeatherShowcase). Re-enabling any of them is a two-line
uncomment, not a rebuild. The other two ideas — the log-stacking scroller
and the wood grain selector — are documented in the scope doc but were
never built.

| Component | Where it plugs in | What it does |
|---|---|---|
| `NotchExplode.tsx` | `/materials` | GSAP-pinned scrollytelling: a full-scribe log joint separates as you scroll, revealing the insulation gasket and concealed fastener, with three sequential callouts |
| `WeatherShowcase.tsx` | `/materials` | Winter/summer toggle showing outside conditions (animated snow/heat particles), a log-wall cross-section, and a steady interior temperature |
| `DayNightShift.tsx` | `/` (home) | Slider morphing a sky gradient + SVG cabin silhouette from day to night, with windows lighting up — placeholder art regardless of the disable, see note below |

`gsap` is still a dependency (used by `NotchExplode`) even while disabled,
in case it's revived. **Before production deploy**, if these aren't
brought back: delete the commented-out lines, remove the three component
files, and uninstall `gsap` if nothing else ends up using it.

**On `DayNightShift` specifically:** independent of the "not up to the
mark" feedback, this one also needs real photography to ever ship. I
wasn't able to pull images from the Instagram account directly —
Instagram blocks automated/robot access to profile pages, and its image
CDN isn't reachable from this build environment either. Ideally: one
bright daylight shot and one dusk/twilight shot of the *same* estate/angle,
so the crossfade reads as one scene changing rather than two different
photos. Worth telling the owner this now, in case the twilight shot isn't
already part of the planned shoot.

## Design tokens

Colors, fonts, and spacing are defined once in `tailwind.config.ts`,
extracted directly from the logo artwork. See the build scope doc for the
full palette table and provenance of each value. When the International
(Oman) site build starts, pull `tailwind.config.ts` + the `components/`
folder into a shared package rather than duplicating them — see Section 4
of the scope doc for the proposed monorepo layout.

## Structure

```
app/            Routes — home + about/services/projects/materials/process/
                gallery/faqs/contact
components/     Shared UI, including the interaction layer above and
                page-level pieces (PageHero, ServiceCard, ProcessSteps,
                FAQAccordion, ContactForm, MobileMenu)
lib/motion.ts   Shared Motion variants, word-split helper, reduced-motion helper
lib/cursor-context.tsx  Lightweight context coordinating the custom cursor
lib/offices.ts  Shared office/location data (Footer + Contact page)
lib/projects.ts Shared project data (homepage carousel + /projects listing)
lib/gallery.ts  Gallery titles/captions (grid + lightbox)
lib/country-codes.ts  Full country calling-code list + flag-emoji helper, for the contact form's phone field
lib/rate-limit.ts  Best-effort in-memory rate limiter for the contact API route
app/api/contact/route.ts  Contact form endpoint — honeypot + rate limit + Turnstile verify, then email via Resend
public/logo.png Brand logo (real asset, from the owner)
```
